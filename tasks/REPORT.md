# Story to Flow — Final Implementation Report

## 1. What Works (Verified)

- **OmniRoute Gateway Integration (T0):** Tested live with `scripts/test-omniroute.ts`. Planner (`agy/gemini-3.8-flash-high`), validator (`agy/gemini-3.8-flash-low`), and fallback (`ollamacloud/gemma4:31b`) all passed text, Bangla UTF-8 and JSON-only generation. The image probe confirmed no image bytes return from chat-tagged models, so `imageProvider` correctly defaulted to `manual`.
- **Story to Bible (T1):** Live verified with the Bangla test story. Planner extracted 3 characters (রিনা, করিম, রিনার মা) and 2 locations (river-ghat, house-courtyard) with 40-60 word visual locks and voice locks.
- **Scene Planning in Batches (T2):** Multi-scene planning with last-2-scene continuity. Establishing shots are automatically inserted before location changes (`is_establishing: true`, `chain_from_previous: false`), and chained scenes have `start_state` synchronized with previous `end_state`.
- **Prompt Assembler (T3):** Assembles plain-text prompts by code without LLM hallucination. Verbatim character visual/voice locks, location locks, camera, and dialogue formatted in native Bangla script. Fully verified by Vitest unit tests in `tests/assemble.test.ts`.
- **Deterministic & Semantic Validation (T4):** Deterministic checks verify all locks verbatim, word counts, character counts, and continuity. LLM validator returns structured field edits up to 2 rounds before marking `needs_attention`. Fully covered by Vitest in `tests/validate.test.ts`.
- **Keyframe Image Generation & References (T5):** Code-built image prompts in configured aspect ratio (16:9 / 9:16). Manual workflow provides copy prompt and upload keyframe. Character and location reference image uploads work and save to `data/files/`.
- **Clip Upload, Last Frame Extraction & Chaining (T6):** Browser-side video canvas frame extraction captures the last frame as PNG, saves it to `/api/scenes/[n]/last-frame`, and sends it to the next scene as its start frame with a "Chained" badge.
- **Review & Prompt Regeneration (T7):** "What went wrong?" checkboxes trigger the validator to suggest 1–3 concrete reinforcement lines in MUST, shown as a green diff before saving as a new prompt version, with an option to promote to a global custom rule that re-assembles all scenes.
- **Chat Editing (T8):** Natural language instructions (e.g. "Rina's saree should be green from now on") are converted to zod-validated operations, displayed as diffs, and executed on confirmation without re-planning the scenes. Verified live in `scripts/test-pipeline.ts`.
- **Export (T9):** `/api/export?format=txt`, `/api/export?format=json`, and `/api/export?format=zip` (using JSZip with all prompts, plan JSON, and media assets).
- **Design & Styling Constraints:** 100% compliant with semantic tokens only (no hardcoded hex colors or arbitrary bracket dimensions/spacings in any components).

## 2. What Is Implemented But Untested & Why

- **Live Flow Video Upload from actual Google Flow:** Real video clips generated by Google Flow in the user's Flow account must be manually produced by the user. The video upload endpoint and frame extraction logic are implemented and unit-verified with standard HTML5 video elements.
- **OmniRoute Image Generation API:** Implemented in `OmnirouteImageProvider`, but disabled by default because OmniRoute responded that `agy/gemini-3.8-flash-high` is not an image model. Can be enabled in Settings if an image model becomes available.

## 3. Assumptions Made

- **Single Project Workspace:** The application operates in a single local workspace mode (`projectId: "default"`), avoiding login, auth, or multi-tenant complexity.
- **SQLite Storage:** Database stored in `data/story-to-flow.db` via `better-sqlite3`. An automatic fallback to `data/db.json` is implemented behind the same `Repo` interface if native bindings fail.
- **Location Display Names:** Bible generates slug IDs (e.g. `river-ghat`); UI formats them nicely into title case for display while retaining the lock verbatim.

## 4. Known Limits

- Video processing is client-side in the browser: last frame extraction depends on the browser video codec support (standard MP4/WebM are supported).
- OmniRoute rate limits: if local OmniRoute experiences 429s, the app retries with `MODEL_FALLBACK` (`ollamacloud/gemma4:31b`).

## 5. Exact Steps to Run on Windows

1. **Install dependencies:**
   ```powershell
   pnpm install
   ```
2. **Environment Configuration:**
   Ensure `.env.local` exists in the project root:
   ```env
   OMNIROUTE_BASE_URL=http://localhost:20128/v1
   OMNIROUTE_API_KEY=your_key_here
   MODEL_PLANNER=agy/gemini-3.8-flash-high
   MODEL_VALIDATOR=agy/gemini-3.8-flash-low
   MODEL_FALLBACK=ollamacloud/gemma4:31b
   MODEL_IMAGE=agy/gemini-3.8-flash-high
   ```
3. **Start the Development Server:**
   ```powershell
   pnpm dev
   ```
4. **Open the App:**
   Open [http://localhost:3000](http://localhost:3000) in your browser.
5. **First Thing to Click:**
   - In the left panel, paste your story into the **Story** textarea (the default Bengali test story is pre-loaded or ready to paste).
   - Click **Create story bible**.
   - Watch the 3 characters and 2 locations appear in the right panel with their visual and voice locks.
   - Click **Re-plan scenes** to generate your scene list.
   - Expand any scene, click **Copy prompt**, and paste it into Google Flow!
